# SDU-Forum 后端测试方案（单元测试 + 全链路集成测试）

## 1. 目标与范围

为 `backend/` 现有分层（Controller → Service → Repository，AppContext 负责装配）补齐：

1. **单元测试**：Controllers、Services、Repositories，以及被它们直接依赖的基础设施（JWT、密码哈希、Middleware）。
2. **集成测试**：以**黑盒 HTTP** 方式启动真实 `sdu_forum_server` 进程 + 真实 MySQL，跑通一条完整 API 链路（注册 → 登录 → 鉴权访问 → 各类错误分支）。

不在本次范围（现状未实现或未接入，避免为测试而改业务）：

- `AuthService::logout / refresh_token / logoff`（仅有声明，`auth_service.cpp` 未实现）；
- `AuthController::logout / refresh_token / logoff`（同上，且路由未注册）；
- `TokenRepository`（`token_repository.cpp` 为空且未加入 CMake）；
- 登录流程中的黑名单分支（`auth_service.cpp` 中已被注释）；
- Blacklist 真实表结构与 `BlacklistRepository` 的 `user_id` 列不一致问题（仅用 Fake 做仓库单测，不做真实库验证）。

## 2. 现状分析（基于实际代码）

| 层 | 文件 | 现状与可测性障碍 |
|---|---|---|
| Controller | `controllers/auth_controller.cpp` | 参数校验逻辑完整，但依赖具体 `service::AuthService&`，无法注入 Fake |
| Service | `services/auth_service.cpp` | 依赖具体 `repository::AccountRepository / BlacklistRepository&`；密码哈希用真实 PBKDF2（可接受） |
| Repository | `repositories/account_repository.cpp`、`blacklist_repository.cpp` | 依赖具体 `dcp::ConnectionPool&`，`get_connection()` 非虚函数，无法 Mock |
| 基础设施 | `token_signer.cpp`、`password_hasher.cpp` | 纯内存逻辑，无 I/O，可直接单测 |
| Middleware | `middleware/auth_middleware.cpp` | 只依赖 Drogon `HttpRequest` 与 `TokenSigner`，可脱离服务器单测 |
| 装配 | `app/app_context.cpp`、`app/modules/auth_module.cpp` | 具体类型逐层注入，适合在 AppContext 中替换为接口实现 |
| 构建 | `backend/CMakeLists.txt` | 所有业务源码直接编进 `sdu_forum_server`，测试目标无法复用，需要抽出静态库 |
| 环境 | 已安装 Drogon 1.9.13、JsonCpp、Boost 1.90、MySQL(3306 可连)、cmake 3.28 | 未安装 gtest/Catch2；Redis(6379) 未启动但当前代码不依赖 |

已确认的关键接口：

- `dcp::IDatabaseConnection` 是全虚接口，但仓库层拿到的是 `dcp::PooledConnGuard`，且 `dcp::IResultSet` 也是全虚接口 → 适合做 Fake。
- `infra::TokenSigner` 构造只需 `(secret, issuer)`，`infra::JwtConfig` 是普通结构体 → Service 单测无需读配置文件。
- `common::AppException` 携带 `ErrorCode`，`common::error_response` 负责映射 HTTP 状态码 → 断言点明确。

## 3. 技术决策（已与用户确认）

1. **测试框架：doctest**，单头文件 vendored 到 `backend/tests/third_party/doctest.h`（版本 `v2.4.11`，实现时用 curl 下载一次并提交）。
2. **允许最小可测性重构**：只做"抽接口 + 改依赖类型 + 新增连接提供者适配器"，不改任何业务逻辑与响应格式。
3. **集成测试走黑盒 HTTP**：独立进程启动 `sdu_forum_server`，使用真实 MySQL，测试进程内用同步 socket HTTP 客户端发请求。
4. 测试构建由 CMake/CTest 统一管理，`unit` 与 `integration` 用 label 区分，默认 `BUILD_TESTING=ON`。

## 4. 生产代码最小重构（不改行为）

### 4.1 新增 `backend/repositories/connection_provider.h` / `.cpp`

目的：让 Repository 不再直接依赖 `dcp::ConnectionPool`，同时保持真实环境下连接自动归还。

```cpp
namespace repository {

// 仓库层实际用到的最小连接能力
class IConnection {
public:
    virtual ~IConnection() = default;
    virtual void prepare_statement(const std::string& sql) = 0;
    virtual void set_string(uint16_t idx, const std::string& value) = 0;
    virtual void set_int(uint16_t idx, int value) = 0;
    virtual std::unique_ptr<dcp::IResultSet> execute_query() = 0;
    virtual int execute_update() = 0;
};

class IConnectionProvider {
public:
    virtual ~IConnectionProvider() = default;
    // 无可用连接时返回 nullptr，仓库层据此抛 DatabaseError（与现状一致）
    virtual std::unique_ptr<IConnection> acquire() = 0;
};

// 生产实现：内部持有 dcp::PooledConnGuard，析构自动归还
class PooledConnectionProvider : public IConnectionProvider {
public:
    explicit PooledConnectionProvider(dcp::ConnectionPool& pool);
    std::unique_ptr<IConnection> acquire() override;
private:
    dcp::ConnectionPool& m_pool;
};

}  // namespace repository
```

- `.cpp` 中实现内部类 `PooledConnection(IConnection)`，成员为 `dcp::PooledConnGuard`，逐方法转发到 `IDatabaseConnection`。
- `acquire()` 中 `auto guard = m_pool.get_connection();`，`operator bool` 为 false 时返回 `nullptr`。
- 把 `connection_provider.cpp` 加入 `sdu_app` 库。

### 4.2 修改 `backend/repositories/account_repository.h` / `.cpp`

- 新增接口（同文件内）：

```cpp
class IAccountRepository {
public:
    virtual ~IAccountRepository() = default;
    virtual std::optional<AccountRecord> find_account_by_user_id(const std::string& user_id) = 0;
    virtual bool insert_account_by_user_id(const std::string& user_id, const AccountRecord& account) = 0;
    virtual bool delete_account_by_public_id(const std::string& public_id) = 0;
};

class AccountRepository : public IAccountRepository { ... };
```

- 构造函数改为 `AccountRepository(repository::IConnectionProvider& provider, std::string account_table)`。
- 成员 `dcp::ConnectionPool& m_pool` → `IConnectionProvider& m_provider`。
- 方法体只改两行：`auto conn = m_provider.acquire();`，其余 SQL/异常处理保持原样（`conn->` 调用不变）。

### 4.3 修改 `backend/repositories/blacklist_repository.h` / `.cpp`

- 同 4.2：新增 `IBlacklistRepository`（`find_active_by_user_id`），构造函数改为接收 `IConnectionProvider&`。

### 4.4 修改 `backend/services/auth_service.h`

- 新增接口并让实现继承：

```cpp
class IAuthService {
public:
    virtual ~IAuthService() = default;
    virtual LoginResult login(const std::string& user_id, const std::string& password) = 0;
    virtual bool signUp(const std::string& user_id, const std::string& password) = 0;
};

class AuthService : public IAuthService {
public:
    AuthService(repository::IAccountRepository& account,
                repository::IBlacklistRepository& blacklist,
                const infra::JwtConfig& jwt_config);
    LoginResult login(...) override;
    bool signUp(...) override;
    ...
};
```

说明：仅把**已实现**的 `login / signUp` 放进接口，避免未实现的 `logout/refresh_token/logoff` 造成 vtable 链接错误；这三个函数维持现状（声明但未定义）。

### 4.5 修改 `backend/controllers/auth_controller.h`

- 成员与构造参数由 `service::AuthService&` 改为 `service::IAuthService&`；`AuthModule` 传入具体实现时隐式向上转型，无需改 `AuthModule`。

### 4.6 修改 `backend/app/app_context.h`

- 增加成员 `repository::PooledConnectionProvider m_db_provider;`（声明在 `m_db_pool` 之后、两个 Repository 之前）。
- 构造函数初始化列表：`m_db_provider(*m_db_pool)`，两个 Repository 改为 `(m_db_provider, table)`。
- 其余生命周期逻辑（`shutdown()`）不变。

## 6. 单元测试设计（逐模块）

通用约定：

- 测试文件用 `TEST_CASE("...")` + `SUBCASE`，命名 `模块.行为.场景`，例如 `"auth_service.login rejects unknown account"`。
- 断言用 `CHECK/REQUIRE`；异常用 `CHECK_THROWS_AS` 并进一步断言 `error_code`。
- 单测禁止访问真实 MySQL/Redis/网络；所有 Repository 通过 Fake 注入。

### 6.1 测试替身设计（`tests/support/`）

- `FakeResultSet : dcp::IResultSet`
  - 以 `std::vector<std::map<std::string,std::string>>` 承载行数据，`next()` 推进游标；
  - `get_string/get_int/get_uint64/is_null` 等按列名取值，缺省列返回空/0；
  - 其余纯虚函数给默认实现，保证可实例化。
- `FakeConnection : repository::IConnection`
  - 记录 `last_sql`、`bound_strings[1..n]`、`bound_ints[1..n]`；
  - 可配置 `query_result`（unique_ptr 工厂）、`update_rows`、`throw_on_query/update`；
  - `execute_query()` 转移结果集所有权，`execute_update()` 返回配置行数。
- `FakeConnectionProvider : repository::IConnectionProvider`
  - `nullptr_mode` 控制返回空连接；否则返回内部 `FakeConnection` 指针供断言。
- `FakeAccountRepository / FakeBlacklistRepository`
  - 可配置返回值/异常；记录 `inserted_record`、`insert_user_id`、调用次数。
- `FakeAuthService : service::IAuthService`
  - 可配置返回 `LoginResult` 或抛 `AppException`；记录调用参数。
- `json_utils.h`
  - `make_request(body, contentType)`：`drogon::HttpRequest::newHttpRequest()` + `setBody` + `setContentTypeCode(CT_APPLICATION_JSON)`；
  - `capture_response(controller_call)`：用 lambda 捕获 `HttpResponsePtr`；
  - `parse_body(resp)`：JsonCpp 解析 `resp->body()`。

## 7. 集成测试设计（黑盒 HTTP 全链路）

### 7.1 测试配置 `tests/integration/config-it.ini`

- `[server] address=127.0.0.1, port=18080, thread_num=2`
- `[log] file=../logs/integration-server.log, console=false`
- `[database]` 同开发环境，`dbname=testdb`，账号密码沿用 `${SDU_DB_PASSWORD:-123456}`
- `[auth]` 固定测试密钥与 `account_table=account_it`、`blacklist_table=blacklist_it`
- 说明：真实表使用 `_it` 后缀，绝不触碰开发表 `account/blacklist`。

### 7.2 支撑组件

- **`MysqlFixture`**
  - 用 `sql::mysql::get_mysql_driver_instance()->connect("tcp://host:port", user, pass)` 连接（配置通过 `infra::AppConfig::load(SDU_FORUM_IT_CONFIG)` 读取，与 server 一致）；
  - `ensure_schema()`：`CREATE TABLE IF NOT EXISTS account_it (...)`（与 `docs/db_sqls.md` 一致，COLLATE `utf8mb4_bin`）；
  - `clean()`：`TRUNCATE TABLE account_it`；
  - `remove_user(user_id)`：测试结束清理。
- **`ServerProcess`（RAII）**
  - `start()`：`fork()` → 子进程 `setenv("SDU_FORUM_CONFIG", config, 1)` 后 `execl(SDU_FORUM_SERVER_BIN, ..., config, nullptr)`；
  - 轮询 `connect(127.0.0.1:18080)`，最多 10s（50ms 间隔），超时则 kill 并报错；
  - `stop()`：`SIGTERM` → `waitpid`（最多 5s）→ 必要时 `SIGKILL`；
  - 启动前先探测端口是否被占用，占用则直接失败并提示。
- **`HttpClient`（同步）**
  - 只支持 `GET/POST` + 自定义 header/body；
  - 发送 `Connection: close`，读取响应直到 EOF，按 `Content-Length` 截取 body；
  - 返回 `{status, headers, body}`，body 用 JsonCpp 解析。
- **固定测试用户**：`user_id` 用 12 位数字（如时间戳后 12 位），密码 `ItPassw0rd!`。

### 7.3 E2E 用例序列（单个 `TEST_CASE`，顺序执行，任何一步失败即终止）

1. Fixture 启动 server，建表并清空 `account_it`。
2. `POST /sdu_forum/api/v1/auth/sign_up` 合法参数 → `200`，`data.state == true`。
3. 重复 sign_up → `400`，`error.code == "INVALID_PARAM"`（"user_id is existed"）。
4. 登录缺 `password` → `400`，`error.code == "INVALID_JSON"`。
5. 登录错误密码 → `401`，`error.code == "INVALID_CREDENTIALS"`。
6. 登录正确密码 → `200`，`data.public_id` 以 `usr_` 开头，6 个 token 字段齐全。
7. `GET /sdu_forum/api/v1/auth/me` 带 `Authorization: Bearer <access_token>` → `200`，`data.public_id` 与登录返回一致。
8. 无 Authorization 访问 `/me` → `401`，`UNAUTHORIZED`。
9. 伪造 token 访问 `/me` → `401`，`UNAUTHORIZED`。
10. 请求体为非法 JSON（`{`）→ `400`，`INVALID_JSON`。
11. 字段类型错误（`user_id: 123`）→ `400`，`INVALID_PARAM`。
12. 结束：删除测试账号、停止 server 进程。

### 7.4 稳定性约定

- 所有 HTTP 断言同时检查 **HTTP 状态码 + `error.code`/`data` 结构**，不依赖 message 文案（避免文案变更导致脆弱）。
- 测试内不 sleep 固定时长；仅在启动时轮询端口。
- 单次 E2E 只启动一个 server 进程（fixture 懒加载，进程退出时回收），避免每个用例重启。

## 8. 实施步骤（执行顺序）

1. 下载 doctest：`curl -fsSL https://raw.githubusercontent.com/doctest/doctest/v2.4.11/doctest/doctest.h -o backend/tests/third_party/doctest.h`。
2. 按第 4 节完成生产代码接口重构，并改造 `backend/CMakeLists.txt`（抽出 `sdu_app`）。
3. 编译现有 server，确认重构无回归。
4. 编写 `tests/support/` 公共替身与工具，再逐个补齐 `tests/unit/`。
5. 编写 `tests/integration/` 支撑组件、配置、E2E 用例。
6. 在 `tests/CMakeLists.txt` 注册两个测试目标，执行第 9 节验证。
7. 修复暴露出的真实缺陷（仅限测试引入的接口问题；不修业务 bug，业务 bug 记录到最终说明中）。

## 10. 假设、风险与边界

1. **MySQL 可用性**：集成测试依赖本机 MySQL；若不可用，集成用例失败并输出明确诊断（不静默跳过）。
2. **Redis 不参与**：当前 token 刷新/吊销未实现，服务启动不初始化 Redis，因此集成测试不需要 Redis。
3. **表结构差异**：`BlacklistRepository` 查询 `user_id`，而 `docs/db_sqls.md` 中 `blacklist` 表为 `account_id`；本次不修，仓库单测用 Fake 覆盖字段映射。
4. **接口重构风险**：仅改依赖类型，不改 SQL、异常码、响应格式；通过编译 + 现有接口 E2E 回归验证。
5. **signUp 现状**：插入失败（0 行）时接口仍返回 200 `state=false`；测试按现状断言，不擅自修改业务语义。
6. **doctest 单头文件**：实现阶段需联网下载一次；下载后随代码提交，后续构建离线可用。
7. **不新增生产依赖**：测试专用代码全部位于 `backend/tests/`，生产二进制不引入 doctest。
